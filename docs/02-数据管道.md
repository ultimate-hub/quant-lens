# 02 - 数据管道：数据是怎么从网上跑到我们数据库里的

> 本篇讲软件的"采购部门"。所有分析都建立在数据之上，数据错了后面全错。

---

## 一、先讲清楚一件事：为什么不能每次查询都去网上抓

假设用户打开网页查"易方达消费"：

- **方案A（直连）**：用户点一次 → 我们去东方财富抓一次 → 返回结果
- **方案B（本地库）**：用户点一次 → 我们查本地数据库 → 返回结果（数据是提前抓好的）

方案A 的三个致命问题：

| 问题 | 具体表现 |
|---|---|
| 慢 | 一次网络请求 200ms~3s，用户会以为网站卡死 |
| 被封 | 100个用户同时查 = 100次请求，对方服务器会直接封我们 IP |
| 不可靠 | 对方接口改版/宕机，我们的网站立刻瘫痪 |

所以正规做法是 **方案B**：定时把数据"同步"到自己的数据库，网页只查本地。

```
东方财富/腾讯财经（数据源）
        │  定时抓取（同步）
        ▼
   本地 SQLite 数据库  ←── 网页查询（毫秒级）
```

## 二、数据源选型：为什么最后没用 akshare

**最初的计划**：用 `akshare` 这个开源库（国内量化圈几乎人手一个）。

**实际遇到的困难**：
1. akshare 依赖极多（py-mini-racer、lxml 等），在你这台机器上安装耗时超过 1 小时仍未完成
2. akshare 本质是"爬虫集合"，它抓的就是东方财富/新浪的公开接口
3. 数据源一改版，akshare 就要跟着发新版，我们的软件会被动等更新

**最终方案**：直接对接底层接口。少一层依赖，就少一类故障。

### 实际使用的三个接口

| 用途 | 接口 | 特点 |
|---|---|---|
| 基金全历史净值 | `fund.eastmoney.com/pingzhongdata/{代码}.js` | **一次请求拿全部**（3911条，0.2秒） |
| 基金名称/类型 | `fundsuggest.eastmoney.com/FundSearch/api/FundSearchAPI.ashx` | 搜索建议接口 |
| 股票日线（前复权） | `web.ifzq.gtimg.cn/appstock/app/fqkline/get` | 腾讯财经，稳定，单次800条 |
| 股票日线（备用） | `push2his.eastmoney.com/api/qt/stock/kline/get` | 东财，近期限流 |
| 基金净值（备用） | `api.fund.eastmoney.com/f10/lsjz` | 每页仅20条，翻页很慢 |

## 三、开发中真实踩到的四个坑（重要经验）

### 坑1：翻页接口只给 20 条

东方财富的 F10 净值接口，即使请求 `pageSize=200`，服务器也只返回 **20 条**：

```
page=1  TotalCount=3911  条数=20
page=2  TotalCount=3911  条数=20
```

一只 2010 年成立的基金有 3911 条净值 → 需要翻 **196 页**，耗时几十秒。

**解决**：换用 `pingzhongdata` 接口。它返回的是一个 JavaScript 文件，里面直接包含全部历史：

```javascript
var Data_netWorthTrend = [{"x":1282233600000,"y":1.0,"equityReturn":0}, ...];
var Data_ACWorthTrend  = [[1282233600000, 1.0], ...];
```

我们用**正则表达式**把这两个数组"抠"出来，再解析成表格。

> 正则表达式：一种文本匹配工具。就像用"从 `Data_netWorthTrend = ` 开始，
> 到第一个分号结束"这样的规则，把中间那段内容取出来。

**效果对比**：196 次请求 / 几十秒 → **1 次请求 / 0.2 秒**。

### 坑2：腾讯接口单次最多 800 条

腾讯的 K 线接口 `param=sh600519,day,,,3000,qfq` 会返回 `param error`。
实测：

```
n=640  -> 641 条  ✅
n=800  -> 801 条  ✅
n=1000 -> 641 条  ⚠️（悄悄降级）
n=3000 -> param error  ❌
```

**解决**：**倒序分页**。从今天开始，每次往前要 3 年（约 640 个交易日），
拿到的最早日期再往前推一天作为新的结束日期，循环直到覆盖目标起始日期。

```
第1轮：2023-11 ~ 2026-10  →  拿到 640 条，最早 2023-11-01
第2轮：2020-12 ~ 2023-10  →  拿到 640 条，最早 2020-12-01
第3轮：2018-01 ~ 2020-11  →  拿到 640 条，最早 2018-01-02  ← 已覆盖 2018-01-01，停止
```

### 坑3：东方财富限流

开发中途，东财的 `push2his` 接口开始返回 `RemoteDisconnected`（服务器主动断开连接），
`urllib` 和 `requests` 都失败，重试 3 次仍然失败 —— 典型的 **IP 限流**。

**解决**：改用腾讯作为主通道，东财降级为备用通道。这就是"主通道+备用通道"设计的意义。

### 坑4：代理环境变量导致所有请求失败

你机器上设置了：

```
HTTPS_PROXY = http://127.0.0.1:7897
HTTP_PROXY  = http://127.0.0.1:7897
```

这是翻墙软件（Clash/V2Ray 之类）的典型配置，**但那个软件没在运行**。
结果所有 HTTP 请求都被送到一个不存在的代理上，直接失败。

**解决**：在代码里加一行：

```python
_session.trust_env = False   # 忽略系统代理设置，直连
```

> 这也是为什么 `pip install` 一直卡住 —— 同一个原因。

## 四、数据库设计（表结构）

SQLite 数据库文件：`quant-platform/data/quant.db`

### 表1：fund_nav（基金净值历史）—— 核心表

| 字段 | 类型 | 含义 |
|---|---|---|
| fund_code | TEXT | 基金代码，如 110022 |
| trade_date | TEXT | 净值日期 YYYY-MM-DD |
| unit_nav | REAL | 单位净值（1份值多少钱） |
| acc_nav | REAL | 累计净值（含分红，衡量真实收益） |
| pct_change | REAL | 当日涨跌幅 % |

**主键 = (fund_code, trade_date)**

> 主键是什么？它规定"这两列的组合必须唯一"。
> 好处：重复插入同一天的数据时，会自动**覆盖**而不是产生重复行。
> 这个特性叫**幂等**（idempotent）—— 同一个操作执行1次和执行100次，结果一样。
> 这样"同步失败重跑"永远安全。

### 表2：fund_info（基金基础信息）

| 字段 | 含义 |
|---|---|
| code | 基金代码 |
| name | 基金名称 |
| fund_type | 类型（股票型/混合型/债券型/指数型） |

### 表3：stock_daily（股票日线）

| 字段 | 含义 |
|---|---|
| code / trade_date | 代码 + 日期（联合主键） |
| open/close/high/low | 开/收/高/低 |
| volume / amount | 成交量（手）/ 成交额（元） |
| pct_change | 涨跌幅 % |

### 表4：sync_log（同步日志）

记录每次抓取的时间、行数、成功/失败、错误信息。
出问题时第一时间看这张表就知道"数据为什么没更新"。

## 五、一个必须懂的概念：复权

**问题**：茅台 2021 年股价 2000 元，2024 年 1500 元，是跌了 25% 吗？
不一定 —— 中间如果每 10 股送 1 股，股价会"除权"跳水，但你的总资产没变。

**如果不复权会怎样**：软件会算出一堆虚假的暴跌，所有指标全错。

**三种复权方式**：

| 方式 | 含义 | 用途 |
|---|---|---|
| 不复权 | 原始价格 | ❌ 不能用来算收益 |
| **前复权** | 以今天为基准，把历史价格调低 | ✅ **回测/分析标准做法**（我们用的这个） |
| 后复权 | 以上市首日为基准，把后面价格调高 | 算长期真实收益 |

我们的腾讯接口参数 `qfq` 就是"前复权"。

## 六、代码结构对照

| 文件 | 职责 | 关键函数 |
|---|---|---|
| `app/services/datasource.py` | 只管"从网上拿数据" | `fetch_fund_nav` / `fetch_stock_kline` |
| `app/services/pipeline.py` | 只管"数据进库/出库" | `sync_fund` / `load_fund_nav` |
| `app/core/db.py` | 只管"数据库连接和建表" | `init_db` / `db_session` |

> **为什么要拆成三个文件？** 这叫**单一职责原则**。
> 将来如果东方财富改版，只需要改 `datasource.py` 一个文件，
> 数据库和计算逻辑完全不受影响。

## 七、实测性能数据

| 操作 | 耗时 | 数据量 |
|---|---|---|
| 同步一只基金全历史（16年） | 0.79 秒 | 3911 条 |
| 同步一只股票 8 年日线 | 0.83 秒 | 2137 条 |
| 从本地库读取 3911 条净值 | ~15 毫秒 | 3911 条 |
| 计算全部 11 项指标 | ~8 毫秒 | — |

结论：**本地查询比网络抓取快约 50-100 倍**，这就是做数据管道的意义。
