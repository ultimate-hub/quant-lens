# 04 - 接口与前端：网页是怎么把数据显示出来的

> 本篇讲"服务员"（后端 API）和"大堂"（前端页面）。

---

## 一、什么是 API

**API（应用程序接口）** 就是"点餐窗口"：

```
顾客（网页）：「我要 110022 这只基金的诊断结果」
服务员（API）：「好的，请稍等」
后厨（计算+数据库）：算好数据
服务员（API）：端出一盘 JSON
```

### 什么是 JSON

一种纯文本数据格式，人和机器都能读：

```json
{
  "info": { "code": "110022", "name": "易方达消费行业股票" },
  "metrics": { "annual_return": 0.0683, "max_drawdown": -0.5732 },
  "score": { "total_score": 27.2, "grade": "较差" }
}
```

## 二、后端技术：FastAPI

### 为什么选 FastAPI

| 优点 | 说明 |
|---|---|
| 自动生成接口文档 | 访问 `/docs` 就能在线测试所有接口，不用手写文档 |
| 自带数据校验 | 参数类型错了自动返回友好错误 |
| 速度快 | 基于 Starlette，性能接近 Node.js |
| 代码即文档 | 一个 `@router.get(...)` 装饰器就定义了一个接口 |

> **装饰器**：Python 里以 `@` 开头的语法糖。
> `@router.get("/funds/{code}")` 的意思是"把下面这个函数注册成
> 一个 HTTP GET 接口，路径是 /funds/xxx"。

### 已实现的接口清单

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 健康检查（确认服务活着） |
| GET | `/api/funds/search?key=` | 搜索基金 |
| POST | `/api/funds/{code}/sync` | 同步基金数据（网络→数据库） |
| GET | `/api/funds/{code}` | **基金诊断（核心接口）** |
| GET | `/api/funds/{code}/nav` | 只取净值序列 |
| GET | `/api/compare?codes=` | 多基金归一化对比 |
| POST | `/api/stocks/{code}/sync` | 同步股票日线 |
| GET | `/api/stocks/{code}` | 股票详情 |

### 为什么有些接口是 POST 而不是 GET

HTTP 语义规范：
- **GET** = 只读，不改变任何东西（查询）
- **POST** = 会产生副作用（同步数据会写数据库）

遵守这个规范的好处：浏览器、缓存、代理、爬虫都能正确对待你的接口。

### 一个贴心的设计：自动同步

```python
if not pipeline.has_fund_data(code):
    pipeline.sync_fund(code)      # 本地没数据就先抓
```

用户第一次查询某只基金时，后端自动去抓数据。
用户不需要知道"同步"这个概念，体验上就是"点一下就出结果"（首次慢1秒，之后秒出）。

## 三、前端技术：为什么用原生 HTML 而不是 Vue/React

| 方案 | 优点 | 缺点 |
|---|---|---|
| Vue/React | 工程化好，适合大团队长期迭代 | 需要构建工具（npm/vite/webpack），上手门槛高 |
| **原生 HTML + JS** | 一个文件搞定，双击就能改，零构建 | 代码量大了不好维护 |

**MVP 阶段的判断**：先验证"客户要不要这个功能"，而不是"架构够不够先进"。
等确认有用户、功能稳定了，再迁移到 Vue 也不迟（接口不用改，只重写前端）。

### ECharts：图表库

百度开源，国内最流行的可视化库。我们做了一件重要的事：

**把 ECharts 下载到本地**（`static/vendor/echarts.min.js`，1MB），而不是用 CDN。

原因：CDN（内容分发网络）在国内经常不稳定，一旦加载失败，
用户看到的是一片空白。本地文件永远可用。

### 三个图表

| 图表 | 类型 | 作用 |
|---|---|---|
| 净值走势 | 折线+面积渐变 | 看长期趋势 |
| 回撤走势 | 折线（水下曲线） | 看历史最惨的时刻 |
| 评分拆解 | 雷达图 | 一眼看出强项弱项 |

## 四、开发中踩的坑：图表被压成一条竖线

**现象**：第一次点"开始诊断"，指标卡片正常，但净值图只有一条垂直的线。

**原因**：
```javascript
renderFund(data);   // ← 图表在这里初始化
show('result');     // ← 结果区到这一步才显示
```

ECharts 初始化时需要测量容器宽高。但那时容器还是 `display:none`（隐藏），
测出来的宽度是 **0 像素**，于是所有数据点挤在 x=0 的位置 → 竖线。

**修复**：调换顺序，并在显示后主动通知图表重新测量。

```javascript
show('result');                    // 先显示容器
renderFund(data);                  // 再初始化图表
[navChart, ddChart, scoreChart].forEach(c => c && c.resize());  // 再测量一次
```

**这个坑的通用规律**：任何图表库（ECharts/Chart.js/D3）在隐藏容器里初始化都会出问题。
以后做"标签页切换"功能时还会再遇到一次。

## 六、一个完整请求的旅程

用户点击"开始诊断"输入 110022：

```
1. 浏览器 fetch('/api/funds/110022')
        ↓
2. FastAPI 路由匹配到 fund_detail(code='110022')
        ↓
3. pipeline.has_fund_data('110022') → True（已同步过）
        ↓
4. pipeline.load_fund_nav('110022') → 3911条净值（15毫秒）
        ↓
5. indicators.compute_all_metrics(nav) → 11项指标（8毫秒）
        ↓
6. indicators.score_fund(metrics) → 27.2分（1毫秒）
        ↓
7. FastAPI 把结果序列化成 JSON
        ↓
8. 浏览器拿到 JSON，ECharts 画出图表
```

**总耗时约 25 毫秒**（不含首次抓数据）。

## 七、安全与合规（面向客户必须注意）

| 事项 | 当前状态 | 上线前必须做 |
|---|---|---|
| CORS 跨域 | 全部放开 `allow_origins=["*"]` | 改成具体域名 |
| 用户认证 | 无 | 加 JWT 登录 |
| 请求限流 | 无 | 加频率限制防刷 |
| HTTPS | 无（本地 http） | 上云后配 SSL 证书 |
| 免责声明 | ✅ 已有 | 律师审核文案 |
| 数据来源声明 | 未标注 | 页面注明数据来源 |
| ICP 备案 | 未办 | 国内服务器必须备案 |

> ⚠️ 特别注意：**数据商用授权**。目前抓的是公开接口，
> 个人研究没问题，但商业化运营有法律风险，上线前需与数据方洽谈授权，
> 或改用持牌数据商（Tushare 高级版 / Wind / 聚源）。
