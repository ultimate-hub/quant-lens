## 二、关键发现（直接影响架构）

### 发现1：腾讯一个源覆盖三个市场 ⭐

```
A股  sh600519  ✅ 251ms
港股  hk00700   ✅  99ms
美股  usAAPL.OQ ✅  99ms
```

**意义**：行情层可以先用腾讯统一实现三个市场，接口简单、速度快（<300ms）。

**限制**：单次最多 640~800 条（约 2.5-3 年），长历史需要倒序分页（v1 已实现这套逻辑）。

### 发现2：Yahoo 是长历史的最佳来源 ⭐

```
Yahoo 美股 AAPL      10年 2513个点  1.5s  ✅
Yahoo 港股 0700.HK   1年 246个点    0.5s  ✅
Yahoo A股 600519.SS  1年 243个点    0.5s  ✅
```

**意义**：Yahoo 一次请求就能拿 10 年数据，比腾讯分页省事。
**结论**：**Yahoo 做美股主通道**（长历史+复权），腾讯做 A股/港股主通道（快）。

### 发现3：东财 F10 财务接口是金矿 ⭐⭐

一个请求返回 **165 个财务字段**，直接覆盖我们需要的全部基本面指标：

| 我们的指标 | 对应字段 | 实测值（茅台2026中报） |
|---|---|---|
| 营业总收入 | `TOTALOPERATEREVE` | 922.78 亿 |
| 归母净利润 | `PARENTNETPROFIT` | 445.17 亿 |
| 营收同比 | `TOTALOPERATEREVETZ` | +1.30% |
| 净利同比 | `PARENTNETPROFITTZ` | -1.95% |
| **加权ROE** | `ROEJQ` | 16.75 |
| 扣非ROE | `ROEKCJQ` | — |
| **毛利率** | `XSMLL` | — |
| **净利率** | `XSJLL` | — |
| **资产负债率** | `ZCFZL` | — |
| 流动比率 | `LD` | — |
| 速动比率 | `SD` | — |
| **ROIC** | `ROIC` | — |
| 每股收益 | `EPSJB` | 35.57 |
| 每股净资产 | `BPS` | 200.99 |
| 每股经营现金流 | `MGJYXJJE` | 56.55 |

还有：应收账款周转天数、存货周转天数、利息保障倍数、经营现金流/净利润比（`NCO_NETPROFIT`）、研发费用占比等。

**意义**：A股的基本面指标可以做到非常完整，不需要买 Wind。

### 发现4：东财快照的数值需要除以 100

```
A股 600519:  PE=1868  PB=662   ROE=16.75
             ↓÷100    ↓÷100
             18.68    6.62    （16.75 不需要除，已经是百分数）
```

**注意**：不同字段的缩放不一致，必须在适配器里逐字段处理。这是容易踩的坑。

### 发现5：东财 push2his 已被限流，但 push2 可用

```
push2his.eastmoney.com (历史K线)  → RemoteDisconnected ❌
push2.eastmoney.com    (实时快照)  → 正常 ✅
```

同一个公司不同子域，一个被限一个正常。所以**不能用"东财挂了"这种粗判断**，
要按具体接口区分。

### 发现6：GDELT 不可用，全球新闻改用 Google News RSS

```
GDELT api  → 20秒超时，返回HTML非JSON ❌
Google News RSS → 3秒，131KB，正常 ✅
```

## 三、最终数据源方案

### 行情（K线）

| 市场 | 主通道 | 备用 | 复权 |
|---|---|---|---|
| A股 | 腾讯 `sh/sz + code` | Yahoo `600519.SS` | qfq 前复权 |
| 港股 | 腾讯 `hk + code` | Yahoo `0700.HK` | qfq |
| 美股 | **Yahoo** `AAPL` | 腾讯 `usAAPL.OQ` | adjclose |

### 基本面

| 市场 | 来源 | 覆盖 |
|---|---|---|
| A股 | 东财 F10 datacenter | ✅ 完整（165字段） |
| 港股 | 东财快照 | ⚠️ 仅 PE/PB/市值 |
| 美股 | 东财快照 | ⚠️ 仅 PB/市值，PE常为0 |

> **明确告知**：美股/港股的估值类指标一期只能给 PE/PB/市值，
> 盈利质量类（ROE/毛利率/负债率）只有 A 股有。UI 上要标注"该市场暂无此指标"，不造假。

### 新闻

| 用途 | 来源 | 接口 |
|---|---|---|
| 中文关键词搜索 | 东财 | `search-api-web.eastmoney.com/search/jsonp` |
| 中文快讯 | 东财 | `newsapi.eastmoney.com/kuaixun/...` |
| 中文财经 | 华尔街见闻 | `dedicated.wallstreetcn.com/rss.xml`（64条） |
| 中文实时 | 新浪 | `zhibo.sina.com.cn/api/zhibo/feed` |
| 全球英文 | Google News | `news.google.com/rss/search?q=` |

### 加密/外汇（二期）

- 加密：`data-api.binance.vision`（镜像，可用）或 OKX
- 外汇：`open.er-api.com/v6/latest/USD`

## 四、统一代码体系设计

为了跨市场统一，定义标准代码格式：

```
{代码}.{市场后缀}
600519.SH    贵州茅台（上交所）
000001.SZ    平安银行（深交所）
00700.HK     腾讯控股
AAPL.US      苹果
BTC.CRYPTO   比特币
```

适配器负责在标准格式和各数据源格式之间转换：

| 标准 | 腾讯 | Yahoo | 东财 secid |
|---|---|---|---|
| 600519.SH | sh600519 | 600519.SS | 1.600519 |
| 000001.SZ | sz000001 | 000001.SZ | 0.000001 |
| 00700.HK | hk00700 | 0700.HK | 116.00700 |
| AAPL.US | usAAPL.OQ | AAPL | 105.AAPL |

> 这张转换表是行情层最核心的东西，写错了整个市场的数据都会错。
> 会为它写专门的单元测试。

## 五、对计划的影响

| 原计划 | 探测后的调整 |
|---|---|
| 美股用 stooq | ❌ stooq 不可用 → 改用 Yahoo |
| 全球新闻用 GDELT | ❌ 不可用 → 改用 Google News RSS |
| 东财做统一行情源 | ⚠️ push2his 限流 → 腾讯做A股/港股主通道 |
| 基本面数据担忧 | ✅ A股完全解决（F10 165字段） |
| 加密一期做 | 延后（Binance主站被限，需镜像） |

**工作量影响**：基本无增加。因为腾讯/Yahoo 都是简单 REST 接口，
比原计划的 stooq CSV 解析还简单。
