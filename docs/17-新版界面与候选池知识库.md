# 17 - 新版界面与候选池/知识库

> 这一版把界面从「能跑就行」重做成有设计的样子，同时加了三个新能力：
> **自定义候选池、搜索联想、市场百科知识库**。

---

## 一、为什么要重做界面

旧版的问题不是"难看"，是**没有信息层级**：

| 旧版 | 问题 |
|---|---|
| 顶部标签页 | 占两行空间，切页面要回顶部找 |
| 综合分一个数字 | 看不出量化分和 AI 分谁在拉高 |
| 价格锚点 5 个灰方块 | 要自己脑补位置关系 |
| 11 个指标平铺 | 没有主次，76 项只能看 11 项 |
| 白底图表 | 线太细，看不出形态 |

新版的设计决定：

1. **左侧固定导航**（分组：分析 / 情报 / 系统），顶栏只放搜索和全局设置
2. **综合分改环形进度**，旁边分列量化和 AI 分数
3. **价格锚点改成一条价格轴** —— 止损 → 买入区间 → 现价 → 目标价，按真实比例摆放
4. **指标网格 + 折叠**：核心 20 项常显，其余 56 项折叠
5. **图表区改深色**，数据线用靛蓝，锚点线直接标在图上

## 二、前端结构（重要：改代码前先看这个）

```
static/app/
├── index.html          外壳：侧边栏 + 顶栏 + 内容容器
├── styles.css          设计系统（所有页面共用，改这里全站生效）
└── js/
    ├── shared.js       工具函数 / API / 全局状态  ← 无副作用，页面都 import 它
    ├── core.js         入口：路由 + 搜索 + 启动    ← 有副作用，只在 index.html 加载
    └── pages/
        ├── analysis.js   个股分析
        ├── screen.js     选股筛选
        ├── watchlist.js  我的候选池
        ├── news.js       新闻情报
        ├── library.js    市场百科
        └── settings.js   设置
```

### 为什么拆 shared.js 和 core.js

一开始我把工具函数和启动逻辑都放在 core.js，结果页面模块 `import { esc } from '../core.js'` 时
会触发 core.js 的启动代码，而且因为循环依赖（core 动态 import 页面，页面静态 import core），
拿到的导出是 undefined，报 `esc is not defined`。

**规则**：
- `shared.js` 只放**无副作用**的东西（函数、常量、状态对象）→ 任何地方可以安全 import
- `core.js` 是**唯一有副作用**的模块（自动 boot）→ 只由 index.html 加载

### 路由

用 hash 路由，不需要服务端配合：

| URL | 页面 |
|---|---|
| `/#/analysis?symbol=600519.SH` | 个股分析（可直接指定标的） |
| `/#/screen` | 选股筛选（支持 `?sector=半导体`） |
| `/#/watchlist?id=2` | 候选池（可定位到某个池） |
| `/#/news?q=半导体&days=7` | 新闻（自动检索） |
| `/#/library` | 市场百科 |
| `/#/settings` | 设置 |

每个页面模块导出 `render(root, ctx)`，`ctx` 提供 `api / state / navigate / toast / confirm`。

## 三、自定义候选池

### 数据存在哪

```sql
watchlists(id, name, note, is_builtin, created_at)
watchlist_items(watchlist_id, symbol, name, industry, note, added_at)
```

**只新增表，不动老表** —— 升级不影响已有的 AI 渠道配置和历史数据。

内置池（`is_builtin=1`）叫「预置·全部板块」，每次打开候选池页会自动从
`app/news/sector_map.py` 同步 30 个板块的 91 只代表个股，不可删除。

### 批量添加的五种方式

| 方式 | 实现 |
|---|---|
| **粘贴代码** | `POST /watchlists/{id}/items` 传 `raw_text`，后端解析 |
| **按板块挑** | 选板块 → `GET /universe?sector=X` → 批量提交 |
| **搜索结果** | 筛选页「加入候选池」 |
| **筛选结果** | 同上，整批导入 |
| **中文名** | 解析器标记为 `name`，走 `registry.search()` 转代码 |

### 解析器（最容易出错的地方）

用户会粘成什么样，谁也猜不到：

```
600519.SH, 000858
00700.HK
AAPL 或直接写中文名：茅台 五粮液
贵州茅台(600519)
SH601318
```

`app/userdata/store.py::parse_symbols()` 的处理顺序：

1. 先把 `名称(代码)` 形式拆开，只留代码
2. 按 `,，、;；空格换行|` 任意分隔符切成 token
3. 逐个判断：
   - `600519.SH` 标准格式 → 直接收
   - 6 位纯数字 → 按首位判断市场（6→沪，0/3→深，4/8→北交所）
   - 5 位数字 → 港股
   - `SH601318` 前缀格式 → 拆开重组
   - 纯字母 → 美股
   - **含中文 → 标为 `name`，留给调用方去搜索**
4. 识别不了的返回 `unknown` 列表，**不静默丢弃**

前端在粘贴框下面实时显示解析结果，绿色的直接认出来，红色的会提示"将自动搜索转换"。

## 四、搜索联想

### 结构

输入「电池」时的下拉：

```
板块
  ◆ 固态电池      查看该板块股票
  ◆ 锂电池        查看该板块股票
个股 / 标的
  野马电池 605378.SH  SH
  ...
最近搜索
  🕐 半导体
```

### 三段来源

| 段 | 来源 | 速度 |
|---|---|---|
| 板块 | 启动时加载的 `state.sectors`（本地数组） | 0ms |
| 最近搜索 | `localStorage` 的 `qt_recent_searches` | 0ms |
| 个股 | `GET /api/v2/search`（东财 + Yahoo） | 300-800ms |

### 为什么要分两段渲染

本地先出结果，联网结果回来了再合并 —— 打字不会卡。
防抖 280ms，键盘 ↑↓ 选择、回车确认、Esc 关闭、Ctrl+K 聚焦。

## 五、市场百科（知识库）

### 为什么做这个

很多回测跑出 300% 收益，是因为**没处理 T+1 和涨跌停**。这些规则不写清楚，
量化结论就是假的。所以每条知识都强制带一栏「对量化分析的影响」。

### 数据结构

`app/library/knowledge.py`，纯静态，32 条，4 个分类：

| 分类 | 条数 | 例子 |
|---|---|---|
| 交易规则 | 8 | T+1、涨跌停、最小单位、交易费用、集合竞价、停牌、除权除息、ST |
| 业务机制 | 9 | 融资融券、沪深港通、打新、可转债、大宗交易、质押、解禁、分红、北向资金 |
| 产品类型 | 8 | 主板、创业板、科创板、北交所、ETF、LOF、REITs、场外基金 |
| 数据与指标 | 7 | 复权、换手率、PE、PB、ROE、龙虎榜、指数编制 |

每条字段：

```python
{
  "id": "t-plus-1",
  "category": "trading",
  "title":   {"zh": "...", "en": "..."},
  "summary": {"zh": "...", "en": "..."},   # 是什么
  "impact":  {"zh": "...", "en": "..."},   # 对分析的影响 ← 核心
  "tags":    ["T+1", "交收"],
}
```

### 语言可配置

设置页的「知识库语言」有三档：仅中文 / 仅英文 / 中英对照。

实现上不分文件，同一条数据里同时放 `zh` 和 `en`，前端按设置取值：

```js
function T(obj) {
  if (lang() === 'en') return obj.en;
  return obj.zh;                  // both 模式主行显示中文
}
function Tsub(obj) {
  if (lang() !== 'both') return '';
  return obj.en;                  // both 模式副行显示英文
}
```

这样加语言只需要在数据里补字段，不用改页面。

### 搜索

后端 `knowledge.search()` 在标题/摘要/影响/标签里做模糊匹配，
搜「涨跌停」能同时命中「涨跌停限制」「ST」「创业板」「科创板」「北交所」——
因为它们的影响栏里都提到了涨跌停。

### 为什么数据源优先级不让改

界面上明确写了原因：A股/港股主用腾讯、美股主用 Yahoo、失败自动切备用 ——
这个顺序是按各源实测可用性调好的，让用户手动打乱会导致部分标的抓不到数据。
**能改的和不能改的，界面上都要说清楚，而不是假装什么都能配。**

## 七、踩过的坑

### 1. ATR 显示 214%

后端 `atr_pct` 已经是百分数（2.14），前端又套了一次 `pct()` 乘 100。
→ 单位转换只在一处做。凡是后端已经带 `_pct` 后缀的字段，前端直接用。

### 2. 涨跌幅显示 +355%

`total_return` 是 2019 年至今的区间收益，放在「现价」旁边会被当成当日涨幅。
→ 后端新增 `daily_change`（最后一个交易日涨跌幅），前端用它。

### 3. 价格轴标签重叠

止损和买入区间挨得近时，文字叠在一起。
→ JS 判断相邻标记距离 < 12% 就给后一个加 `row2` 类，标签下移一行，轴高度从 74px 增到 106px。

### 4. 核心指标网格右下角出现灰块

指标数量不是列数的整数倍，空格子露出了网格背景色。
→ 补齐到 5 的整数倍，空位用 `--surface-2` 的同色块占位。

### 5. 新闻 AI 总是回退到规则引擎

一次给 AI 送 20 条新闻，输出太长导致超时/解析失败，后端静默降级成规则引擎，
看起来像"AI 没工作"。
→ 拆成两个请求：新闻列表取 20 条（给人看），给 AI 的只送 8 条。实测 8.3 秒成功。
→ 界面明确标注「规则引擎」还是「AI」，不让用户误以为是 AI 的结论。

### 6. `esc is not defined`

页面模块从 core.js 导入工具函数，遇到循环依赖拿到 undefined。
→ 拆出无副作用的 `shared.js`（详见第二节）。

### 7. 改了后端代码但接口还是旧结果

`Start-Process` 启动新进程时端口被旧进程占着，静默失败，一直在跑旧代码。
→ 杀进程要按命令行匹配，不能只按端口：

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like "*serve.py*" } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```
