## 一、为什么要把「板块」重做

旧版的 `sector_map.py` 是一张写在代码里的静态表：30 个板块，混着行业和主题，
用户改不了，新闻匹配也只能命中这 30 个。

重做后的两层结构：

| 类型 | 含义 | 特征 | 数量 |
|---|---|---|---|
| **行业** industry | 稳定的产业分类 | 一家公司通常只属于一个，切换慢 | 22 |
| **概念** concept | 主题投资标的 | 跨行业、随行情快速轮换，一股可属多个 | 27 |

比如「比亚迪」既属于行业「新能源汽车」，也属于概念「锂电池」「储能」。
这不是重复，而是两种看问题的角度。

### 落地方式

```
app/concepts/
├── seed.py    内置数据（22 行业 + 27 概念，136 只股票）
└── store.py   存储层：内置 + 用户自定义，CRUD + 关键词匹配
```

数据表：

```sql
concepts(id, name, kind, note, is_builtin, sort_order)
concept_items(concept_id, symbol, name)
concept_aliases(concept_id, alias)
```

**首次运行自动灌种**，之后用户改了就保留 —— 不会下次启动又被覆盖。

### 用户能自定义什么

| 操作 | 内置概念 | 自建概念 |
|---|---|---|
| 加/减成分股 | ✅ | ✅ |
| 加/删别名 | ✅ | ✅ |
| 改名 | ✅ | ✅ |
| 改类型（行业↔概念） | ✅ | ✅ |
| 删除整个概念 | ❌（防止误删） | ✅ |

### 别名是干什么的

新闻里写「算力租赁」，程序怎么知道该归到「AI算力」？
靠别名。别名列表参与关键词匹配：

```
AI算力: [算力, 智算中心, GPU, AI服务器, 算力租赁]
```

### 新闻模块怎么接上

`sector_map.py` 变成了一层**合并视图**：

```python
def _merged():
    merged = {静态30个板块}
    merged.update(概念库的全部概念)   # 数据库
    return merged
```

如果数据库读失败，就退回静态表 —— **新闻功能不能因为数据库问题挂掉**。

## 二、走势推演：必须先把话说清楚

### 这不是预测

没有任何方法能预测未来价格。这里做的是：

> 假设「未来的日收益分布和过去相似」，用历史日收益做有放回抽样，
> 生成 N 条可能的未来路径，画出它们的分布带。

界面上明确标注「非价格预测」，并且写明三条局限：
不考虑政策、不考虑业绩突变、不考虑流动性冲击。

### 为什么用自举而不是正态分布（GBM）

股票日收益不服从正态分布：有厚尾（暴涨暴跌比正态多）、有波动聚集（大跌后继续大波动）。

- 正态假设：会系统性低估极端行情
- 自举法：直接复用真实历史收益样本，厚尾特性自然保留

### 为什么用「块自举」

完全独立抽样会破坏短期相关性（A 股常有连续几天同向）。

所以按 **5 天为一块**抽样，保留一周内的动量/反转结构。

### 为什么固定随机种子

不固定的话每次刷新数字都变，用户会以为程序在乱跳。

种子 = `md5(代码 + 当天日期)` → 同一天内结果稳定，跨天自然更新。

### 输出什么

```
起始价 85.15
第 20 交易日：
  5% 分位   63.80   (-25.1%)
  25% 分位  ...
  50% 分位  88.90   (+4.4%)   ← 中位路径
  75% 分位  ...
  95% 分位 126.69   (+48.8%)
上涨概率 58.2%
触及目标价概率 81.7%
触及止损价概率 10.4%
先到目标价 812 / 先到止损 73 / 都没碰到 115
```

「先到哪边」这个统计特别有用 —— 它回答的是「这笔交易在我被迫止损之前，
先摸到目标的概率有多大」，比单纯看上涨概率贴近实盘。

## 三、配仓建议：规则驱动，不交给 AI

### 为什么不交给 AI

AI 给的建议无法追溯。用户看到「建议买入 10%」时，没法核对这个数字怎么来的。
规则引擎的每条结论都带 `basis` 字段，写明计算方式：

```
[!] 风险收益比不划算
    风险收益比 0.95，低于 1 意味着上行空间小于下行风险
    依据：(目标价 - 现价) / (现价 - 止损价)
```

### 动作判定（关键：站在「还没买」的视角）

这个软件主要给准备建仓的人用，所以：

| 现价位置 | 动作 | 说明 |
|---|---|---|
| 跌破止损位 | **止损离场** | 未持仓不要抄底；已持仓按规则走 |
| 低于买入区间下沿 3% 以上 | **分批建仓**（评分≥50）／等待 | 低位但要确认不是基本面坏了 |
| 落在买入区间内 | **分批建仓** | 正常买点 |
| 略高于区间上沿（8% 内） | **回踩加仓** | 别追，等回踩 |
| 高于区间上沿 8% 以上 | **等待回落** | 追高不划算 |
| 达到目标价 95% 以上 | **到目标价 · 减仓** | 已持仓减半；未持仓别新建 |

**之前踩过的坑**：一开始我用了「持有观望」这个动作，结果对没持仓的用户毫无意义；
而且「接近目标价」时显示「分批建仓」的标签配「建议减仓」的文案，自相矛盾。
现在统一成「未持仓视角为主，已持仓在文案里并列说明」。

### 仓位怎么算

```
基础仓位   = 锚点算法给出的 position_pct（风险预算法：单笔最大亏损 2%）
× 评分因子  综合分 ≥70 → 1.0；55-70 → 0.9；45-55 → 0.7；<45 → 0.45
× 波动因子  年化波动 >35% → 0.8
× 超买因子  RSI >75 → 0.7
× 模拟因子  触及止损概率 >35% → 0.8
最终 clamp 到 [3%, 25%]
```

每个因子触发时都会生成一条带数字的说明。

### 分批计划

不管当前动作是「建仓」还是「等待」，都会输出 3 档买入计划 ——
因为等待的人也需要知道「跌到哪该动手」。

| 档位 | 价位 | 占总仓 |
|---|---|---|
| 一档 | 买入区间上沿 | 40% |
| 二档 | 区间中值 | 35% |
| 三档 | 逼近止损上方 | 25% |

### 触发条件

| 类型 | 动作 |
|---|---|
| 止损 | 跌破即离场，不摊平不补仓 |
| 止盈 | 触及先减一半，剩余把止损上移到成本价 |
| 回踩 | 回到区间下沿附近，是第二档加仓点 |

## 四、这一轮修掉的 bug

### 1. 买入区间塌缩成一个点

宁德时代出现 `买入区间 220.41 ~ 220.41`，导致「分批」变成同一个价买三次。

原因：支撑位候选 `[ma20, ma60, ma120, low_60, low_250]` 去重后如果只剩 1 个满足
`0 < x < price`，`buy_low` 和 `buy_high` 就都取到它。

修复：强制最小宽度约 3%：

```python
if buy_high <= buy_low:
    buy_high = min(price * 0.99, buy_low * 1.03)
```

### 2. 目标价取到 None

我一开始用了 `bundle["anchors"]`，但那个是原始计算结构，字段名不一样。
合并后的结果是 `bundle["final"]`。用错导致「触及目标价概率」永远是 None。

### 3. 建议动作与文案矛盾

见第三节。

### 4. 种子数据里的过时名称

验证 136 个代码时发现：

| 代码 | 写错 | 实际 |
|---|---|---|
| 603501.SH | 韦尔股份 | 豪威集团（已改名） |
| 002739.SZ | 万达电影 | 儒意电影（已改名） |
| 300212.SZ | 易华录 | **\*ST易录**（已变 ST，换成 300226.SZ 上海钢联） |

**这 136 个代码是逐个用腾讯行情接口验证过的**，全部有效。
校验脚本的思路：批量请求 `qt.gtimg.cn/q=`，解析返回里的名称字段，
名称为空就是无效代码。

## 五、新增接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v2/concepts` | 列出概念（可按 kind / 关键词过滤） |
| GET | `/api/v2/concepts/{id}` | 单个概念的成分股与别名 |
| POST | `/api/v2/concepts` | 新建（可同时带别名和成分股） |
| PUT | `/api/v2/concepts/{id}` | 改名 / 改类型 / 改备注 |
| DELETE | `/api/v2/concepts/{id}` | 删除（内置不可删） |
| POST | `/api/v2/concepts/{id}/items` | 加成分股 |
| DELETE | `/api/v2/concepts/{id}/items` | 减成分股 |
| POST | `/api/v2/concepts/{id}/aliases` | 加别名 |
| DELETE | `/api/v2/concepts/{id}/aliases` | 删别名 |
| GET | `/api/v2/outlook/{symbol}` | 推演 + 情景 + 建议（一次拿全） |
| GET | `/api/v2/advice/{symbol}` | 只要建议（不跑模拟，快） |

`/api/v2/sectors` 的定义也变了：现在返回概念库的全部名称，
所以搜索联想自动包含用户新建的概念。

## 六、界面

### 新页面：概念库

- 左侧：按「行业 / 概念」分组列出，带成分股数量，自建概念有标记
- 右侧：成分股列表（可移除、可直接跳分析）、别名管理（点 × 删除）
- 顶部：搜索（名称或别名）、按类型过滤、新建概念

### 分析页新增两块

1. **走势推演**（深色卡片）
   - 扇形图：5%/25%/50%/75%/95% 五条分位线，两层区间带
   - 三张情景卡：悲观 / 中性 / 乐观
   - 概率条：上涨概率、触及目标、触及止损
   - 「先到哪边」统计
   - 明确的免责说明

2. **配仓建议**
   - 动作标签 + 目标仓位
   - 一句话结论
   - 判断依据（每条带依据说明）
   - 三档分批计划表
   - 触发条件
