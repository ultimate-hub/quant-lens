# 05 - 运行手册：怎么把软件跑起来

> 本篇是"操作说明书"。哪怕你完全不懂技术，照着做也能跑起来。

## 一、启动（日常使用就这一条）

打开一个命令行窗口，进入项目目录，执行：

```powershell
cd D:\AgentLand\量化分析软件\quant-platform
& "C:\Users\杨\.dsh\dsh-runtimes\dsh-next-primary-runtime\dependencies\python\python.exe" run.py
```

看到下面这段输出就成功了：

```
========================================================
  量化分析平台已启动
  网页界面: http://127.0.0.1:8000
  接口文档: http://127.0.0.1:8000/docs
  按 Ctrl+C 停止
========================================================
INFO:     Uvicorn running on http://127.0.0.1:8000
```

然后在浏览器打开 **http://127.0.0.1:8000** 即可。

> 💡 想关掉服务：在命令行窗口按 `Ctrl + C`。

## 二、三个网址分别是什么

| 网址 | 是什么 |
|---|---|
| http://127.0.0.1:8000 | **给客户看的网页界面** |
| http://127.0.0.1:8000/docs | 接口文档，可以在线点"Try it out"测试 |
| http://127.0.0.1:8000/api/health | 健康检查，返回 `{"status":"ok"}` 说明服务活着 |

> `127.0.0.1` 是"本机地址"，只有你这台电脑能访问。
> 要让别人访问，需要部署到服务器（见文末）。

## 三、怎么用

1. 在输入框输入 **6 位基金代码**，例如 `110022`
2. 点"开始诊断"（或直接按回车）
3. 首次查询需要 1-2 秒（正在抓取该基金全部历史数据）
4. 之后同一个基金再查就是**毫秒级**（数据已在本地）

**常用基金代码**：

| 代码 | 名称 |
|---|---|
| 110022 | 易方达消费行业股票 |
| 161725 | 招商中证白酒指数 |
| 005827 | 易方达蓝筹精选混合 |
| 000961 | 天弘沪深300ETF联接A |
| 110011 | 易方达中小盘混合 |

**多基金对比**：在"多基金对比"框输入 `110022,161725,000961`，点对比。

## 四、日常维护：每天更新数据

目前是"查询时自动同步"。如果要每天收盘后批量更新（推荐做法），
可以加一个定时任务。

### 方式A：手动批量同步（简单）

```powershell
cd D:\AgentLand\量化分析软件\quant-platform
& "...\python.exe" -c "import sys; sys.path.insert(0,'.'); from app.services import pipeline; [print(pipeline.sync_fund(c)['name'], '已更新') for c in ['110022','161725','000961']]"
```

### 方式B：Windows 任务计划程序（自动）

1. 打开"任务计划程序"
2. 创建基本任务 → 每天 20:00（基金净值一般晚上8点后更新）
3. 操作选"启动程序"，程序填 python.exe 的完整路径，参数填 `run_sync.py`
4. 起始位置填 `D:\AgentLand\量化分析软件\quant-platform`

> 后续可以做一个 `run_sync.py` 脚本批量同步"自选基金池"。

## 六、常见问题排查

### 问题1：网页打不开 / 显示"无法访问此网站"

**检查**：命令行窗口还在运行吗？如果关掉了，服务就停了，需要重新启动。

**检查端口占用**：
```powershell
netstat -ano | findstr :8000
```
如果有别的程序占用 8000 端口，改 `run.py` 里的 `port=8000` 为 `8001`。

### 问题2：点"开始诊断"报错"数据同步失败"

**原因**：网络问题，或者数据源限流。

**排查步骤**：
1. 先访问 http://127.0.0.1:8000/api/health，确认服务本身正常
2. 换一个基金代码试试（可能是单只基金的问题）
3. 等几分钟再试（可能是 IP 被限流）
4. 查看 `data/quant.db` 里的 `sync_log` 表，看具体错误

### 问题3：所有网络请求都失败（pip 装不上、数据抓不到）

**原因**：系统代理环境变量指向了一个没运行的程序。

**检查**：
```powershell
echo $env:HTTPS_PROXY
```
如果输出 `http://127.0.0.1:7897` 之类，说明有代理配置。

**说明**：我们的代码里已经加了 `_session.trust_env = False` 自动绕过，
所以数据抓取不受影响。但 `pip` 命令仍然会受影响，安装新库时需要先：
```powershell
$env:HTTPS_PROXY=""; $env:HTTP_PROXY=""
```

### 问题4：图表不显示 / 显示成一条竖线

**原因**：ECharts 在隐藏容器里初始化，宽度测成 0。

**当前状态**：已修复（先显示容器再初始化图表）。
如果以后再出现，检查 `static/index.html` 里 `analyze()` 函数的顺序。

### 问题5：数据库文件在哪？能删吗？

位置：`D:\AgentLand\量化分析软件\quant-platform\data\quant.db`

- **能删**：删掉后下次查询会自动重建并重新抓数据（只是要重新抓一遍）
- **建议备份**：直接复制这个文件就是完整备份

## 八、下一步：从本机到上线

当前状态是**本机可用的 MVP**。要让真实客户访问，需要这些步骤：

| 步骤 | 内容 | 大概工作量 |
|---|---|---|
| 1 | 买云服务器（2核4G，约100元/月） | 半天 |
| 2 | 域名 + ICP备案（国内必须） | 2-3周（备案慢） |
| 3 | 装 Python 环境 + 上传代码 | 半天 |
| 4 | 用 systemd/supervisor 守护进程（崩溃自动重启） | 半天 |
| 5 | 配 Nginx 反向代理 + HTTPS 证书 | 半天 |
| 6 | 加用户系统（注册/登录） | 1-2周 |
| 7 | 数据商用授权洽谈 | 视情况 |
| 8 | 律师审核免责声明与用户协议 | 1周 |

**建议顺序**：先做 6（用户系统）之前，找 5-10 个真实用户试用本机版本，
验证"他们到底会不会用、愿不愿意付钱"，再投入服务器成本。
