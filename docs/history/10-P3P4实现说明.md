## 一、P3 AI 网关

### 1.1 为什么这块特别难

你用的**全部是中转站**，不是官方 API。中转站和官方 API 有 6 个实际差异：

| 差异 | 后果 | 我们的解法 |
|---|---|---|
| 模型名被改写 | 硬编码模型名必然失效 | 模型名手填 + `/v1/models` 一键拉取 |
| 协议不统一 | Claude 官方是 Anthropic 协议 | 双协议适配器 |
| 不支持 JSON 模式 | 结构化输出直接失败 | 能力探测 + 三级降级 |
| 不支持流式 | 请求卡住 | 探测后自动用非流式 |
| 不支持某些参数 | 返回 400 | 自动删参数重试 |
| 限流/502 | 偶发失败 | 重试退避 + 多渠道路由 |

### 1.2 密钥安全：Windows DPAPI

```
原文:   sk-test-1234567890abcdef
密文:   AQAAANCMnd8BFdERjHoAwE/Cl+sBAAAA33uPY8sjE0e8BkBLFYRZ6Q...
解密:   sk-test-1234567890abcdef   ✅
界面显示: sk-t********cdef
```

**原理**：调用 Windows 内置的 `CryptProtectData`，加密结果绑定"本机+本账户"。
即使数据库文件被拷走，换台电脑也解不开。

**为什么不用 keyring 库**：少一个依赖就少一个安装失败的可能。DPAPI 用 ctypes 直接调系统 API，零安装。

### 1.3 双协议适配

```python
# OpenAI 兼容（DeepSeek/Kimi/通义/智谱/OpenRouter/本地Ollama）
POST {base}/v1/chat/completions
Authorization: Bearer sk-xxx
body: {model, messages, temperature, max_tokens, response_format?}

# Anthropic 原生（Claude 官方）
POST {base}/v1/messages
x-api-key: sk-xxx
anthropic-version: 2023-06-01
body: {model, max_tokens, system, messages}   ← system 是独立字段
```

URL 拼接兼容三种用户输入：
```
https://api.deepseek.com/v1           -> .../v1/chat/completions
https://xxx.com                       -> .../v1/chat/completions
https://xxx.com/v1/chat/completions   -> 原样使用
```

### 1.4 JSON 三级降级（最关键）

```
第1级：response_format={"type":"json_object"}   ← 探测支持才用
   ↓ 400/被忽略
第2级：剥掉 ```json 围栏 + 截取最外层 {...}
   ↓ 解析失败
第3级：修复语法（中文引号/多余逗号/单引号键/Python字面量）
   ↓ 仍失败
兜底：返回原文 + 标记"未能结构化解析"
```

**实测效果**：模拟服务器返回下面这种"脏数据"：

```
好的，以下是分析结果：

```json
{"ok": true, "from": "fenced", "score": 88,}
```

希望对你有帮助！
```

解析结果：`{'ok': True, 'from': 'fenced', 'score': 88}`，方法标记为 `repair`。
注意那个多余的逗号 `88,}` —— 被第3级修复掉了。

### 1.5 能力探测（Capability Probe）

配置一个渠道后自动跑一次，结果存库：

```
正常渠道: 模型列表=True system=True JSON模式=True  延迟=2ms
挑刺渠道: 模型列表=True system=True JSON模式=False 延迟=1ms
```

**开发中发现的语义 bug**：第一版探测把"挑刺渠道"判定成支持 JSON 模式。
原因：探测用的是 `chat()`，而 `chat()` 遇到 400 会自动删掉 `response_format` 重试，
于是"降级成功"被误判成"原生支持"。

**修复**：探测必须绕过降级逻辑，直接发原始请求看状态码。

### 1.6 多渠道故障切换

```
优先级：指定渠道 > 默认渠道 > 其余启用渠道（最多试3个）

实测：把"死链"设为默认 →
  ✅ 自动切换成功，实际使用: MOCK-正常
```

每次调用都记入 `ai_usage` 表：渠道、任务、成败、延迟、token 数、错误信息。

## 二、P4 AI 定性分析

### 2.1 核心设计：先算，再让 AI 解释

**错误做法**：直接问 AI"这只股票目标价多少" → AI 编一个看起来合理的数字。

**正确做法**：
```
程序算候选价位 → 交给 AI → AI 只能"选择并解释" → 程序校验选择是否合法
```

### 2.2 价格锚点怎么算（`analytics/anchors.py`）

| 价位 | 计算方法 | 实测（茅台，现价1355.9） |
|---|---|---|
| 买入区间 | 支撑位：MA20/MA60/MA120/近60日低/近250日低 | 1157.5 ~ 1252.8 |
| 目标价 | 技术阻力位（近3月/1年/2年高点）+ 估值回归法 | 1361.8 / 1814.6 |
| 止损位 | `min(现价-2×ATR, 近60日低×0.97)`，且不低于现价75% | 1021.3 (-24.7%) |
| 仓位 | 风险预算法：单笔最大亏损2% / (每股风险/价格) | 12% |

**估值回归法**（A股可用）：
```
TTM每股收益 = 现价 / 当前PE
目标价 = TTM每股收益 × 目标PE（15/20/25/30倍）
```
这样目标价有明确依据："PE 回到 20 倍对应多少钱"。

### 2.3 Prompt 设计的三条铁律

```
1. 你只能使用用户提供的【数据事实】，绝对不许自己回忆或编造任何财务数字
2. 目标价/买入区间/止损位只能从【候选价位】中选择，或说明"均不合理"
3. 必须同时列出看多和看空的理由，不允许只说好话
```

**关键点**：数据由程序算好放进 prompt，AI 只做判断和解释。
这样即使 AI 模型较弱，也不会编造财务数据。

### 2.4 防幻觉校验（三道闸）

**第一道：目标价必须在候选列表里**

```
AI 给出 999999 → 不在候选 [1361.8, 1814.6] 中
  → 回退到最近候选 1814.6
  → 告警："⚠️ AI给出的目标价999999.0不在候选列表中（疑似编造），已回退到最近的候选1814.64"
```

**第二道：买入区间必须合理**（开发中实测发现的漏洞）

AI 给出了 `85.0 ~ 92.0`，而现价是 1355.9 —— 偏离 15 倍。
第一版校验没拦，直接把荒谬数字展示出来了。

修复：区间必须落在现价的 50%~105% 之间，否则改用系统支撑位区间。

**第三道：止损价必须低于现价**

```
AI 给出止损 1021（高于现价？不，低于）
但在幻觉案例里 AI 给了 749999 → 高于现价 → 改用系统止损
```

### 2.5 最终结论的合成逻辑

```
综合分 = 量化分与AI分按分析模式的权重加权
       = 量化分 × (1 - AI权重) + AI分 × AI权重
```

AI 分不是"覆盖"量化结论，而是作为 `sentiment` 维度融入评分体系。
**权重的控制权始终在用户手里**（通过切换分析模式）。

实测（茅台）：
```
量化分 57.0  +  AI分 72.0  →  综合分 58.5
维度: 估值43.3 成长37.5 质量94.5 动量54.8 风险53.6 情绪72.0
```

### 2.6 降级能力：没有 AI 也能用

```
不启用AI（无key场景）:
  腾讯控股 综合分 42.0 评级 中性
  目标价 492.2 止损 365.6
  ✅ 量化部分独立可用
```

这很重要：**你还没配 key 的时候，软件依然能出完整量化报告**。
AI 只是增强，不是依赖。

### 2.7 无财务数据的市场怎么办

苹果（美股）实测：
```
维度: valuation=19.0 momentum=79.8 risk=67.0 sentiment=72.0
（成长、质量维度缺席，权重自动重新归一化）
```

Prompt 里会明确告诉 AI：
> "该标的暂无完整财务数据（非A股市场）。请勿在分析中提及 ROE、毛利率、负债率等财务指标，因为你没有这些数据。"

**这是防止 AI 编造财务数据的关键一句话**。

## 三、验证方式：模拟中转站

因为拿不到真实 key，我写了一个模拟服务器（`tools/mock_llm_server.py`）模拟四种真实场景：

| 路径 | 模拟行为 |
|---|---|
| `/ok/` | 完全规范的 OpenAI 兼容接口 |
| `/picky/` | 拒绝 `response_format`（返回400）—— 很常见 |
| `/fenced/` | 忽略JSON模式，返回带 ```json 围栏和解释文字 + 多余逗号 |
| `/hallucinate/` | 返回编造的目标价 999999 |
| `/ratelimit/` | 返回 429 |
| `/v1/messages` | Anthropic 原生协议 |

**这是本次开发最重要的验证手段**——没有真实 key 也能把网关的每条降级路径都跑一遍。

## 五、你接下来需要做的

等 P5 完成后，就可以配置真实中转站了：

1. 打开软件设置页
2. 选一个预设（或"自定义中转站"）
3. 填 `base_url`、`key`、`模型名`
4. 点"测试连接" → 自动探测能力
5. 保存

**建议**：配置 2 个渠道（一个便宜的做新闻摘要，一个强的做个股分析），
网关会自动按任务路由，贵的模型只在关键分析时调用。
