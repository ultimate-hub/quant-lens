# 12 - 桌面打包排障记录（真实踩坑全过程）

> 打包成 exe 这件事，踩了 6 个坑，耗时约 1.5 小时。
> 记录在这里，以后重装/换机器不用再踩一遍。

---

## 一、最终方案

```
量化终端.exe
  ├─ 后台线程启动 FastAPI（自动找空闲端口）
  ├─ 等 /api/v2/ping 返回 200
  ├─ 用 Chrome/Edge 的 --app 模式开窗口（无地址栏）
  ├─ 前端每 10 秒 ping /api/health 报活
  └─ 90 秒收不到心跳 → 判定窗口关闭 → 自动退出
```

产物：`dist/量化终端/` 整个文件夹，101.8 MB。

## 二、六个坑，按发现顺序

### 坑1：窗口模式下 `print()` 直接崩溃

**现象**：双击 exe，什么都不发生，没有窗口，没有日志，进程秒退。

**根因**：PyInstaller 的 `--windowed` 模式会把 `sys.stdout` 设成 `None`。
代码里第一行 `print("正在启动…")` 立刻抛 `AttributeError`，
而且异常处理里的 `print` 又崩一次，所以什么都看不到。

**解决**：
```python
def log(msg):
    line = f"[{time.strftime('%H:%M:%S')}] {msg}"
    with open(LOG_PATH, "a", encoding="utf-8") as f:   # 先写文件
        f.write(line + "\n")
    if getattr(sys, "stdout", None) is not None:        # 有控制台才打印
        print(line)
```

### 坑2：emoji 在 GBK 控制台抛异常

**现象**：控制台版本报 `UnicodeEncodeError: 'gbk' codec can't encode character '\u2705'`

**根因**：Windows 控制台默认 GBK 编码，`print("✅")` 直接崩。

**解决**：启动时强制 UTF-8 + 输出只用 ASCII 标记：
```python
for s in (sys.stdout, sys.stderr):
    try: s.reconfigure(encoding="utf-8", errors="replace")
    except Exception: pass
# 之后用 [OK] / [ERROR] / [WARN] 代替 emoji
```

### 坑3：数据库写进了临时目录

**现象**：exe 每次重启，AI 渠道配置和缓存全丢。

**根因**：`BASE_DIR = Path(__file__).parent.parent.parent`
在打包后指向 `sys._MEIPASS`（临时解压目录），程序退出就删。

**解决**：区分"只读资源"和"可写数据"：
```python
if getattr(sys, "frozen", False):
    RESOURCE_DIR = Path(sys._MEIPASS)              # static 在这
    BASE_DIR = Path(sys.executable).parent          # 数据库放这
else:
    RESOURCE_DIR = BASE_DIR = Path(__file__).parent.parent.parent
```

### 坑4：字符串动态导入在打包后失效

**现象**：`uvicorn.Config("app.main:app")` 打包后找不到模块。

**解决**：直接传对象
```python
from app.main import app as fastapi_app
uvicorn.Config(fastapi_app, ...)
```

### 坑5：pythonnet 在中文路径下加载失败

**现象**：
```
RuntimeError: Failed to resolve Python.Runtime.Loader.Initialize
from D:\...\量化分析软件\...\_internal\pythonnet\runtime\Python.Runtime.dll
```

**根因**：pywebview 依赖 pythonnet，而 pythonnet 处理含中文的路径会失败。
本项目路径是 `D:\AgentLand\量化分析软件\`，必然踩坑。

**解决**：
1. 打包时排除 `webview / clr / pythonnet`（省 40MB，也避免崩溃）
2. 桌面窗口改用**浏览器应用模式**（`--app=` 参数，无地址栏）

### 坑6（最隐蔽）：子进程继承了 PyInstaller 的 PATH

**现象**：exe 里调用 Chrome `--app=` 启动窗口，Chrome 进程秒退，
但同样的代码在源码模式下完全正常。

**排查过程**：
- 手动用相同参数启动 Chrome → 正常，profile 目录被创建
- exe 里启动 → profile 目录根本没创建，说明 Chrome 没真正跑起来
- 对比两者环境变量 → 发现 PyInstaller 把 `_internal` 目录塞进了 PATH

**根因**：Chrome 继承了这个 PATH，加载到 `_internal` 里的同名 DLL
（版本不匹配）→ 启动即崩溃。

**解决**：启动子进程前清理环境变量，并完全分离进程：
```python
env = os.environ.copy()
if getattr(sys, "frozen", False):
    env["PATH"] = os.pathsep.join(
        p for p in env["PATH"].split(os.pathsep)
        if "_internal" not in p.lower() and "_MEI" not in p)
    for k in ("_MEIPASS", "PYTHONHOME", "PYTHONPATH"):
        env.pop(k, None)

flags = 0x00000008 | 0x00000200    # DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP
subprocess.Popen(args, env=env, close_fds=True, creationflags=flags)
```

## 三、还有一个逻辑坑：不能用"启动器进程退出"判断窗口关闭

**现象**：窗口刚打开就变白，后端被关掉了。

**根因**：Edge/Chrome 已经开着窗口时，再执行 `msedge.exe --app=...`，
启动器进程会**立刻退出**（只是把命令转交给已有实例），
而窗口还在加载。如果这时 `proc.wait()` 返回就关服务，页面必然白屏。

**解决**：改用**心跳机制**
```
前端：setInterval(() => fetch('/api/health'), 10000)
后端：heartbeat.touch() 记录时间戳
桌面：每5秒检查，超过90秒没心跳就退出
```

**配套细节**：就绪探测要用 `/api/v2/ping` 而不是 `/api/health`，
否则启动器自己的探测会污染心跳，导致"前端还没连上"被误判成已连上。

## 五、如果换一台电脑部署

| 情况 | 处理 |
|---|---|
| 有 Chrome 或 Edge | 直接双击 exe 即可 |
| 都没有 | 自动退回默认浏览器（有地址栏） |
| 杀毒软件拦截 | 加入白名单（PyInstaller 产物常见误报） |
| 想改端口 | 改 `desktop.py` 的 `DEFAULT_PORT` |
| 想重新打包 | `python build_exe.py`（约 70 秒） |

**分发方式**：把 `dist/量化终端` 整个文件夹压缩成 zip。
不要只拷 exe —— 它依赖同目录的 `_internal` 文件夹。
