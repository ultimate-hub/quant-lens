# 15 - AI 连接失败怎么自己排查

> 起因：配了中转站，分析时报
> `SSL: UNEXPECTED_EOF_WHILE_READING`，看着像软件坏了，实际是**域名拼错了一个字母**。

---

## 一、本次真实案例复盘

### 现象

页面底部提示：
```
AI 分析未完成：所有渠道都失败 -> ds: 请求失败（已重试）:
SSLError: HTTPSConnectionPool(host='sub.skypomo.top', port=443):
Max retries exceeded ... [SSL: UNEXPECTED_EOF_WHILE_READING]
```

### 排查过程（4 步，10 分钟）

| 步骤 | 做什么 | 发现 |
|---|---|---|
| 1 | 直接测 HTTPS 请求（直连 + 走代理） | 两种都 SSL 握手失败 |
| 2 | 测裸 TCP + TLS 握手 | 到 443 端口能连，但 TLS 阶段被断开 |
| 3 | 查 DNS | 解析到 `198.18.0.16` ← **RFC2544 保留段，代理软件的假 IP** |
| 4 | 用公共 DNS（IP 直连，绕过本地劫持）查域名 | `skypomo.top` → **NXDOMAIN 域名不存在** |

### 真因

**域名拼写错误**：配的是 `skypomo.top`，实际应该是 `skypoem.top`。
一个字母之差（o ↔ e），DNS 查不到，代理软件给了个假 IP 顶上去，TLS 自然失败。

改正后：
```
sub.skypoem.top  → 172.64.229.217（Cloudflare）  ✅ 连接正常
```

## 二、三步自查法（以后遇到直接照做）

### 第 1 步：确认域名是否真实存在

打开 PowerShell，执行（把域名换成你的）：

```powershell
nslookup sub.skypoem.top 223.5.5.5
```

**怎么读结果**：

| 结果 | 含义 |
|---|---|
| 返回正常 IP（如 172.64.x.x） | ✅ 域名有效 |
| 返回 `198.18.x.x` / `198.19.x.x` | ⚠️ 代理软件的假 IP，域名可能有问题 |
| 提示 `Non-existent domain` | ❌ 域名不存在，**拼错了或已失效** |

> `198.18.0.0/15` 是代理软件（Clash/Surge 等）TUN 模式专用的假地址段。
> 看到这个网段，说明 DNS 被本地代理接管了，不代表域名真存在。

### 第 2 步：验证 key 和地址是否匹配

在软件「AI 设置」页，点渠道右边的 **「探测」** 按钮。

| 探测结果 | 说明 |
|---|---|
| 模型列表=True | ✅ base_url 正确 |
| 模型列表=False，但对话成功 | base_url 少了或多了 `/v1` |
| 全部失败 + SSL 错误 | 域名/网络问题，看第 1 步 |
| 全部失败 + 401 | key 错了 |
| 全部失败 + 404 | base_url 路径不对 |

### 第 3 步：看软件给的提示

现在软件会把技术错误翻译成人话，例如：

- 「域名解析失败：这个域名不存在或已失效 → 请回到中转站网站确认最新地址」
- 「SSL 握手被中断... ① 域名已失效 ② 代理软件转发失败 ③ IP 被封」
- 「密钥无效或已过期（HTTP 401）→ 检查 API Key 是否复制完整」
- 「接口地址不正确（HTTP 404）→ 检查 base_url，常见错误是多了或少了 /v1」

## 三、常见原因对照表

| 错误关键词 | 真实原因 | 怎么修 |
|---|---|---|
| `NXDOMAIN` / `域名不存在` | 域名拼错或已失效 | 回中转站网站复制最新地址 |
| `UNEXPECTED_EOF` / `SSLEOFError` | 域名失效 / 代理转发失败 | 先查域名，再试把该域名设为直连 |
| `401 Unauthorized` | key 错误或过期 | 重新复制 key（注意别带空格） |
| `403 Forbidden` | key 没权限 | 确认该 key 能用这个模型 |
| `404 Not Found` | base_url 路径错 | 通常是 `/v1` 的问题，试试加或去掉 |
| `429 Too Many Requests` | 限流 | 等几分钟，或降低并发 |
| `timeout` | 网络慢/节点差 | 换节点，或换一个中转站 |
| `Insufficient balance` | 余额不足 | 充值 |

## 四、关于代理软件（重要）

你的机器开了代理（`127.0.0.1:7897`），且是 **TUN 模式**（劫持全局 DNS）。

这带来两个影响：

1. **DNS 全部返回假 IP**（198.18.x.x），所以 `nslookup` 要用 `223.5.5.5` 指定外部 DNS 才准
2. **我们的代码默认忽略系统代理**（`trust_env=False`），走的是"直连假 IP"这条路，
   然后由代理软件在底层接管

**如果某个 API 连不上，可以尝试**：

- 在代理软件里把该域名加入**直连白名单**
- 或切换代理模式（TUN → 系统代理）
- 或换一个节点

**不需要改代码** —— 实测两种模式（直连/走代理）都能通，取决于代理软件配置。

## 五、本次顺带修的一个 bug

测试时发现：**AI 返回的 JSON 是数组 `[{...}]` 而不是对象 `{...}` 时，程序会崩**。

```
错误：'list' object has no attribute 'get'
```

已修复：现在会自动从数组里提取第一个对象，并在结果里标注"AI返回的是数组，已提取第一个对象"。

## 六、AI 分析耗时说明

实测茅台一次完整分析：

```
总耗时 52.3 秒（其中 AI 调用 49.8 秒）
```

**为什么这么慢**：中转站需要排队，且要生成 400+ 字的结构化分析。

**能不能更快**：
- 换更快的中转站/模型（如 deepseek-chat 而非推理模型）
- 或关闭「启用 AI 定性分析」只看量化结果（2-3 秒出结果）

量化部分和 AI 部分是独立的 —— AI 慢不影响你先看指标。
