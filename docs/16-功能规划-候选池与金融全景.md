## 二、需求 1：用户自定义候选池

### 2.1 产品形态

```
我的候选池
├── 核心持仓（12只）      ← 用户自建
├── 白酒观察（4只）        ← 用户自建
├── 半导体全板块（5只）    ← 从板块一键导入
└── 预置·全部板块（91只）  ← 系统内置，不可删
```

### 2.2 批量添加的五种方式（这是你要的"一次性批量选择"）

| 方式 | 操作 | 场景 |
|---|---|---|
| **A. 粘贴代码** | 文本框粘一堆代码，支持逗号/空格/换行/中文名混合 | 从别处复制一堆股票 |
| **B. 板块勾选** | 左边板块列表 → 右边该板块所有股票 → 全选/勾选 | 「把半导体板块都加进来」 |
| **C. 搜索结果勾选** | 在搜索页多选结果 → 加入指定池 | 搜到一批想关注的 |
| **D. 筛选结果导入** | 筛选出 12 只 → 「全部加入候选池」 | 先筛再存 |
| **E. 文件导入** | 导入 CSV / TXT（一列代码） | 从 Excel 导出 |

### 2.3 核心设计：**批量解析要能容错**

粘贴时用户可能给的是：
```
600519,五粮液,000858 贵州茅台
600519.SH
茅台
```
解析器要能识别：纯代码、带后缀、中文名、混排。
识别不了的**列出来让用户确认**，不静默丢弃。

### 2.4 数据表

```sql
CREATE TABLE watchlists (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE,
    note TEXT,
    is_builtin INTEGER DEFAULT 0,      -- 预置池不可删
    created_at TEXT
);

CREATE TABLE watchlist_items (
    watchlist_id INTEGER,
    symbol TEXT NOT NULL,               -- 标准格式 600519.SH
    name TEXT,                          -- 冗余存名字，避免每次查
    note TEXT,
    added_at TEXT,
    PRIMARY KEY (watchlist_id, symbol)
);
```

### 2.5 界面

筛选页的「候选池」下拉从：
```
全部板块（约100只）
```
变成：
```
预置·全部板块（91只）
──────────────
核心持仓（12只）
白酒观察（4只）
──────────────
＋ 新建候选池…
⚙ 管理候选池
```

### 2.6 一个关键取舍

**候选池要不要支持"批量 AI 分析"？**
- 91 只全跑 AI：按每只 50 秒算，**耗时 75 分钟**，费用也不低
- 建议：只支持「批量量化分析」（13 秒，已有），AI 分析仍然是单只点开才跑
- 见 Q7

## 三、需求 2：搜索联想（像浏览器）

### 3.1 现在的问题

现在的下拉只有标的：
```
贵州茅台 600519.SH    SH
```

你要的是"相关股票或板块提示"。

### 3.2 新设计：分组下拉

输入「电池」时显示：

```
┌─────────────────────────────────────────────┐
│ 板块                                         │
│  🔷 固态电池        宁德时代、国轩高科…      │  ← 点击进板块
│  🔷 锂电池          赣锋锂业、天齐锂业…      │
├─────────────────────────────────────────────┤
│ 个股                                         │
│  宁德时代 300750.SZ  SZ                     │
│  国轩高科 002074.SZ  SZ                     │
├─────────────────────────────────────────────┤
│ 相关（固态电池板块代表股）                    │
│  欣旺达 300207.SZ                           │
├─────────────────────────────────────────────┤
│ 最近搜索                                     │
│  🕐 半导体                                   │
└─────────────────────────────────────────────┘
```

### 3.3 技术方案

新增 `GET /api/v2/suggest?q=电池`

后端聚合三路：
1. **板块匹配**：`sector_map.map_text(q)` → 命中板块 + 代表股
2. **标的搜索**：`registry.search(q)`（现有，联网，约 300ms）
3. **本地历史**：最近 10 条搜索记录（存 SQLite）

### 3.4 性能设计（关键）

现有搜索是**实时联网**（东财 + Yahoo），300-800ms。
如果每敲一个字就搜，会慢且可能触发限流。

方案：
- **防抖 300ms**（现有逻辑已有）
- **本地优先**：先查本地板块表 + 缓存的股票清单（毫秒级）立即出结果
- **联网补充**：异步请求，回来后再合并进下拉
- **本地股票缓存**：把搜索过的标的存本地，2000 条以内，命中率会很高

这样：打字 → 立即看到板块提示 → 300ms 后看到精确标的。

### 4.2 数据表

```sql
CREATE TABLE user_settings (
    key TEXT PRIMARY KEY,
    value TEXT,          -- JSON
    updated_at TEXT
);
```

用一个 KV 表存所有设置，避免频繁改表结构。

### 4.3 一个诚实的设计决定

「高度个性化」听着很爽，但**有些东西不能真的让用户改**：

| 能改 | 不能改（会直接坏） |
|---|---|
| 启用哪些市场 | 数据源的具体接口地址 |
| 基准指数选哪个 | 指标计算公式 |
| 并发数、缓存时长 | 数据库路径 |
| 默认模式、默认池 | — |

所以设置页要**分组**：「可自由调整」 vs 「高级（谨慎修改）」。

## 五、需求 4：中国金融全景（⚠️ 范围最大，必须划边界）

### 5.1 先说明白：这件事没有"做完"的一天

中国金融市场包含：
```
股票（主板/创业板/科创板/北交所/新三板/B股）
基金（股票型/混合/债券/指数/QDII/FOF/货币）
ETF、LOF、REITs、可转债
债券（国债/地方债/企业债/可交换债）
期货（股指/商品/国债）、期权
逆回购、理财、大额存单
打新、配股、增发、可转债申购
融资融券、股票质押、转融通
港股通、沪深港通、北向/南向资金
龙虎榜、大宗交易、盘后固定价格交易
限售解禁、股权激励、股东大会
分红送转、除权除息
```

**如果全部做成"可分析的功能"，工作量是现在的 5-10 倍，而且很多数据源拿不到。**

所以我建议做成**三层结构**，按"能做的价值"排序：

### 5.2 第一层：产品导航（可点击 → 进入分析）

一个「产品中心」页面，把可分析的品种分类呈现：

```
📈 股票
   主板 / 创业板 / 科创板 / 北交所 / 港股 / 美股
📊 基金
   场内 ETF / LOF / 场外基金（v1 已有基金诊断）
📄 债券
   可转债 / 国债逆回购
🌐 指数
   沪深300 / 中证500 / 科创50 / 恒生 / 纳斯达克…
```

每个品种卡片显示：
- 支持状态（✅ 可完整分析 / ⚠️ 仅行情 / ❌ 未支持）
- 当前数量（如"沪深A股 5,300 只"）
- 点击 → 进入该类的筛选/列表

**价值**：用户知道"这个软件能分析什么、不能分析什么"，而不是盲猜。

### 5.3 第二层：市场规则知识库（可查询，纯静态）

一个「市场百科」页面，用结构化条目解释：

```
【交易规则】
  T+1 制度           股票当日买入次日才能卖
  涨跌停限制          主板 ±10% / 创业板科创板 ±20% / ST ±5% / 北交所 ±30%
  最小交易单位        100 股（1 手）
  交易费用           佣金(万2.5默认) + 印花税(卖出千1) + 过户费(万0.1)

【业务机制】
  融资融券            标的范围、保证金比例、维持担保比例
  港股通              额度、标的范围、汇率结算、交易时间差异
  打新（新股申购）     市值配售规则、申购流程、中签率
  可转债申购          信用申购、破发风险
  大宗交易            门槛、折价率、T+1 限制
  股票质押            质押率、平仓线

【对分析的影响】   ← 这一栏最重要
  T+1  → 回测不能用"当日买入当日卖出"，会高估收益
  涨跌停 → 涨停买不进、跌停卖不出，回测必须模拟
  ST 股 → 涨跌停 ±5%，且多数策略应剔除
  停牌 → 停牌期间无法交易，净值要按停牌前价格计算
```

**为什么这一层有价值**：这些规则**直接决定量化回测的真假**。
很多人回测出 300% 收益，就是因为没处理 T+1 和涨跌停。

内容用 JSON 存储（`app/library/knowledge/*.json`），支持搜索。

**规模**：先做 20-30 条核心条目，后续可扩充。不需要联网。

### 5.4 第三层：实时榜单（需要数据源，要探测）

| 榜单 | 数据源 | 可行性 |
|---|---|---|
| 龙虎榜 | 东财 datacenter | 待探测 |
| 大宗交易 | 东财 datacenter | 待探测 |
| 融资融券余额 | 东财 | 待探测 |
| 北向/南向资金 | 东财 | 待探测（2024年后停止实时披露，可能只有日度） |
| 涨停/跌停板 | 东财 | 待探测 |
| 板块涨幅榜 | 东财 | 较可能可用 |
| 主力资金流向 | 东财 | 待探测 |

**必须先探测再承诺**。拿不到的就不做，不造假。

## 十、需要你决定的额外一件事

**这个项目要不要从"个人工具"转向"能给别人用的产品"？**

如果是后者，还要考虑：
- 用户数据隔离（虽然本地不需要）
- 多语言
- 版本升级机制（数据表迁移）
- 更严格的错误提示

如果是前者（自己用），上面这些都可以简化。
