## 一、这个软件是什么

一句话：**一个帮普通客户看懂和分析 A 股股票与国内基金的网站工具**。

用户打开网页后可以：
1. **查数据**：看股票K线、基金净值走势、基金基本信息
2. **做诊断**：输入一只基金代码，软件给出收益、回撤、波动率、夏普比率等评分
3. **分析组合**：导入自己持有的多只基金，看行业分布、风险集中度
4. **回测策略**：模拟"如果我三年前开始每月定投这只基金会怎样"

## 二、软件的分层结构（为什么要分层）

想象一家餐厅：
- **数据层** = 采购食材（从公开渠道获取股票/基金原始数据）
- **计算层** = 后厨做菜（把原始数据加工成"夏普比率""最大回撤"这些结论）
- **后端 API** = 服务员（在网页和后厨之间传递请求和结果）
- **前端** = 餐厅大堂（用户看到的页面）

分层的好处：某一层坏了或要升级，不影响其他层。这是所有正规软件的标准做法。

```
用户浏览器
   │  (HTTP请求，如"查询基金110022的净值")
   ▼
FastAPI 后端  ←——— 你看到的网址背后跑着的程序
   │
   ├──► 指标计算模块（纯数学，pandas库）
   │
   └──► 数据库（SQLite文件，存净值历史）
            ▲
            │ 收盘后定时抓取
        数据管道模块（akshare库 → 东方财富等公开数据）
```

## 三、技术选型及原因（为什么选这些）

| 组件 | 选择 | 通俗解释 | 为什么选它 |
|---|---|---|---|
| 编程语言 | Python 3.12 | 写软件的语言 | 金融数据分析生态最全，没有之一 |
| 数据获取 | akshare | 一个免费开源的"数据搬运工"库 | 免费、无需注册、覆盖股票+基金 |
| 数据处理 | pandas | 处理表格数据的库，金融界标配 | 所有量化工作都建立在它之上 |
| 数值计算 | numpy | 高速数学运算库 | pandas的地基 |
| 数据库 | SQLite | 一个文件就是一个数据库 | 零配置，MVP阶段最合适 |
| 后端 | FastAPI | 把Python函数变成网页API的框架 | 速度快、自动生成接口文档、现代 |
| 前端 | 原生HTML + ECharts | 网页 + 免费图表库（百度开源） | MVP阶段不引入复杂前端框架，先跑通 |
